Cloud computing is part of everyday technology, from storing files online to running applications and business systems. But putting something in the cloud does not automatically make it secure.

This guide is made for college students and beginners who already know a little about technology or cloud computing but are new to cloud security. It breaks the topic into smaller sections so the different parts are easier to understand.

01. Understanding Cloud Computing and Cloud Security

Before getting into cloud security, it helps to understand how cloud services are organized. Three common service models are Infrastructure as a Service (IaaS), Platform as a Service (PaaS), and Software as a Service (SaaS).

These models give customers different levels of control over the technology they use. That difference also affects which parts of security belong to the cloud provider and which parts remain the customer's responsibility.

02. Common Security Risks and Vulnerabilities

Security problems are not always caused by a major outside attack. Problems can also begin with weak access controls, incorrect settings, or other configuration mistakes.

This is why cloud security involves more than responding to hackers. Organizations also have to think about how their systems are designed, configured, and managed before a security problem happens.

03. Who Is Responsible for Cloud Security?

Using a cloud provider does not mean the provider handles every part of security. Cloud security uses a shared responsibility model, which divides responsibilities between the cloud provider and the customer.

AWS explains that the provider is responsible for the infrastructure its services run on, while customers are still responsible for areas such as their data, accounts, applications, and some of the security settings they choose.

Responsibility changes with the service

Microsoft Azure's shared responsibility guidance also shows that the customer's role changes depending on whether the service is IaaS, PaaS, or SaaS. As the provider manages more of the technology, the customer may manage less of the underlying system, but responsibilities involving data and accounts still remain important.

04. Protecting Data and Access

Moving information to the cloud does not remove an organization's responsibility to think about how that information is protected. Organizations still need to consider who can access their data, how access is controlled, and what security and privacy decisions remain their responsibility.

Questions to keep in mind

  • Who should be able to access the information?
  • What permissions does each account actually need?
  • How is activity monitored for possible security problems?
  • How are data protection and privacy considered when the cloud environment is designed?

Protecting data and controlling access are closely connected. If access is not managed carefully, the information itself can become harder to protect.
